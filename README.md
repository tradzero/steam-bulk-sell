# Steam 批量出售 · 本地版 v0.1.1

一个自用、可审计的 Chrome Manifest V3 扩展。工作台在扩展自己的标签页中运行：选择同质库存、核对数量和价格，然后填入 Steam 原生 `multisell` 页面。最终创建上架和手机确认由用户在 Steam 完成。

## 安装

1. 解压 `steam-bulk-sell-v0.1.1.zip` 到一个长期保留的目录。也可以直接使用源码项目中已经构建好的 `dist/`。
2. 在 Chrome 地址栏打开 `chrome://extensions/`。
3. 打开右上角“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择含有 `manifest.json` 的解压目录，或本项目的 `dist/`。不要选择 ZIP 文件或项目外层目录。
5. 在 Chrome 扩展菜单中固定“Steam 批量出售 · 本地版”。

安装不会要求访问所有网站，也不会注入常驻脚本。扩展仅在点击工具栏图标后获得对应标签页的临时访问能力。插件文件目录需要持续存在；移动或删除后应重新加载。

## 使用

1. 在 Chrome 登录 Steam，打开自己的库存或社区市场，点击扩展图标。
2. 从市场启动时，原标签页会转到自己的库存，另开本地工作台。请保留原 Steam 标签页。
3. 选择“游戏与库存”，点击“加载库存”。分页完全加载成功后才能继续。
4. 按名称和类型筛选，选择当前页、全部筛选结果，或应用“每种保留 N 件”。首版不会预选新库存。
5. 获取已选物品的参考价，选择定价策略后点“应用到已选”；也可切换“价格输入口径”，直接编辑每件到手价或买方支付价（与参考价同口径）。获取行情本身不会修改价格。
6. 点击“核对出售清单”。逐行查看数量、到手价、买方价、合计，以及缺失/过期/偏低的参考价提示。
7. 确认后进入 Steam 原生页面。扩展重新检查账户、库存、费用和输入框，再填入数量和价格。
8. 在 Steam 页面再次核对，自己点击“创建上架物品”；如 Steam 要求手机或邮件确认，按其原生流程完成。
9. 下一批请先回到自己的库存，再点击扩展。对同一 Steam 标签页重复点击图标会复用当前工作台，避免多个工作台争用同一页面。

“清单已交接”仅表示填充完成，不代表已上架或已成交。刷新 Steam 原生页面会丢失插件填入的值，页面可能恢复其默认数量和价格；刷新后务必重新检查。

## 首版功能与边界

- 库存完整分页读取，按 `market_hash_name` 合并。
- 只纳入 Steam 返回 `marketable=1` 且 `commodity=1` 的物品。不会凭物品名称推断其同质性。
- 搜索、类型筛选、排序、分页多选、只看已选、保留数量。筛选外的选择会明确计数，并全部显示在核对单。
- 手动输入可切换到手价 / 买方支付价（参考价口径）；切换会换算所有已填写行，包括筛选外的行。无效价格需先修正。
- 参考最低在售价、低一个货币步长、按参考价百分比调整策略支持两种输入口径。
- 库存列表与核对单显示每件手续费，底部显示手续费合计。手续费为实际买方支付减到手金额。
- 买方输入价遇到费用取整差异时，输入框下显示实际买方价；核对与原生交接使用实际金额。草稿保存到手金额，重新打开默认以到手价显示。
- 买方支付与卖方到手同时展示；价格计算使用整数单位，并按 Steam 当前费用和取整规则校验。
- 参考价 5 分钟后标为过期；明显低于参考价 20% 时提示。无参考行情时可手动定价，但必须额外确认。
- 保存本次浏览器会话中的草稿和缓存。关闭浏览器、关闭来源 Steam 标签页、手动清除，或两小时未使用后失效。没有云同步。
- 每批最多 25 种 / 200 件；每个库存上下文最多读取 20,000 个资产；一次只处理一个游戏/库存上下文。
- 不处理独立属性皮肤、交易请求、买单、撤单、自动改价、自动手机确认或自有出售队列。
- 原生页面开始提交后的进度、部分失败、待确认与成交结果，均以 Steam 显示为准。首版不提供对 Steam 内部提交队列的暂停/重试控制。

有些游戏的专属费用可能与 Steam 原生批量页面使用的费用不同。出现这种情况会停止填充，而不是强行使用另一套价格。

## 构建与验证

Node.js 22 或更高版本（本次使用 Node.js 24）。生产扩展没有 npm 运行时依赖；TypeScript、Chrome 类型和 jsdom 仅用于开发/测试。

```sh
npm ci --ignore-scripts
npm test
```

`npm test` 会先编译并构建 `dist/`，再运行测试。无需在测试中登录 Steam，不会发送出售请求。

```sh
npm run package
```

打包脚本使用系统 `zip` 命令，在项目父目录生成可加载 ZIP、源码 ZIP 和校验文件。Windows 可在构建后手工压缩 `dist/`。

本地演示使用相同界面代码，但只操作测试数据：

```sh
npm run build
python3 -m http.server 8765 --bind 127.0.0.1 --directory .preview
```

在浏览器打开 `http://127.0.0.1:8765/ui.html#demo`。演示适配器不包含在发布插件包中。

## 文件

- `src/background.ts`：会话、消息授权、读取节奏、只读请求和原生交接调度。
- `src/steam.ts`：Steam 页面边界。MAIN 仅读取白名单上下文/费用和填充原生表单；库存和行情 GET 在 ISOLATED 环境发起。
- `src/core.ts`：金额、费用、分页合并、批次和核对单验证。
- `src/ui.ts`、`static/ui.*`：本地工作台。
- `tests/`：金额、分页、授权、原生填充和安全边界测试。
- `dist/SHA256SUMS`：当前构建产物的 SHA-256 清单。
- `SECURITY.md`：权限、网络目标、残余风险和更新方式。
- `VALIDATION.md`：本次验证证据与尚未验证的部分。

## 常见问题

**启动时提示未登录或页面变化**：等待 Steam 库存加载完成；确认是自己的库存；重新点击扩展。缺少必要字段时插件不会猜测继续。

**“库存未完整返回”**：加载中发生网络错误、重复分页或库存变化。重新完整加载；不能用已经读取的部分库存生成核对单。

**Steam 限流（429）**：停止本轮请求，不自动重试。行情请求会设置至少 60 秒的本地冷却，再由你决定是否重试。

**行情价格无法解析**：不会从多个数字中猜价格。可以手动定价并在核对页确认风险提示。

**交接失败**：结构或价格不匹配时，已识别的目标数量会归零。不要重复点击 Steam 提交；回到库存重新读取。若原生页面改版，需要更新适配器。

**最终交易是否已经验证**：没有。见 `VALIDATION.md`。本次没有安装到用户 Chrome，也没有创建真实上架。
